# 高并发测试报告

## 测试环境

- 测试时间：2026-05-15
- 目标：`http://localhost:3008`
- 服务：本机 Node.js / Express / MySQL
- 压测工具：`tools/load-test.js`
- Postman GUI 已安装，但本机未发现 `newman` CLI；本次使用 Node 原生 HTTP 压测脚本执行并发测试。

## 测试命令

```powershell
node tools\load-test.js http://localhost:3008/ 100 10
node tools\load-test.js http://localhost:3008/novel/1/4 50 10
node tools\load-test.js http://localhost:3008/admin/login 50 10
```

后台管理页需要登录 Cookie，测试时先登录获取 `admin_session`，再压测 `/admin`。

## 结论

- 所有压测场景均无请求错误，服务稳定性通过短时高并发验证。
- 静态/轻逻辑页面 `/admin/login` 吞吐最高，说明 Express 本身不是主要瓶颈。
- 章节页吞吐明显低于首页和登录页，100 并发时 P95 接近 1 秒，主要压力来自章节正文读取、段落拆分、EJS 渲染和访问统计写入。
- 后台管理页在 20 到 50 并发时吞吐基本不提升，稳定约 155 RPS，说明后台页查询、章节列表渲染或 MySQL 连接池存在上限。
- 前台请求每次都会异步写入 `page_views`，高并发下会给 MySQL 带来额外写入压力。

## 优化建议

1. 给前台目录页、章节页增加短 TTL 缓存，缓存渲染后的 HTML 或查询结果。
2. 将 `page_views` 写入改为内存队列批量落库，避免每个请求都触发一次独立 INSERT。
3. 章节正文页可以缓存 `paragraphs` 拆分结果，减少每次请求的字符串处理成本。
4. 后台章节列表增加分页或虚拟滚动，不要一次渲染全部章节。
5. 数据库连接池 `connectionLimit` 当前是 10，可按服务器配置调整并配合 MySQL 最大连接数测试。
6. 生产部署建议使用 Nginx gzip/br 压缩和静态资源缓存头。
